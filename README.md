# Reward Model

Automatic dense-reward construction and visual reward-model training for robot
manipulation.

This repository is the standalone Reward Model portion extracted from
[`Caiyishuai/Rsync`](https://github.com/Caiyishuai/Rsync). It intentionally does
not contain `hil-serl`, robot drivers, ROS packages, or real-robot deployment
code.

## What is included

The repository supports the complete reward-model workflow:

```text
binary success/fail demonstrations
  → stage discovery
  → dense potential labels
  → DINO + temporal reward model
  → held-out signal evaluation
  → online RM or PBRS reward
```

Implemented environments:

- MetaWorld 3.1: Button-Press, Window-Open, Reach-Wall, Plate-Slide, Push,
  Coffee-Push, Stick-Push and Pick-Place.
- ManiSkill3: PushCube, PokeCube, PlaceSphere and StackCube.
- Existing real-robot demonstration formats registered in `data/common.py`.

## Repository layout

```text
data/                 Task registry, datasets and preprocessing
label/                G-HMM/prototype stage discovery and dense labels
scripts/              Collection, validation, training and evaluation entrypoints
sim/                  ManiSkill online RM/PBRS reward integration
tests/                Unit and integration tests
reward_model.py       DINO + temporal ensemble reward model
train.py              Reward-model training
evaluate.py           Held-out reward-model evaluation
eval_suite.py         Unified evaluation suite
```

Generated demonstrations, checkpoints and evaluation outputs are intentionally
gitignored. Reproduce them with the documented commands.

## Installation

Linux/NVIDIA is required for full visual RM training.

```bash
git clone https://github.com/Caiyishuai/reward-model.git
cd reward-model

python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install torch==2.6.0 torchvision==0.21.0 \
  --index-url https://download.pytorch.org/whl/cu124
python -m pip install -e .
```

Install environment-specific extras:

```bash
# MetaWorld collection
python -m pip install -e ".[metaworld]"

# ManiSkill simulation
python -m pip install -e ".[sim]"

# Development
python -m pip install -e ".[dev]"
```

## MetaWorld eight-task workflow

Collect 20 successful scripted demonstrations and 20 random-policy failures per
task. Each transition contains a 39-D goal-observable state, a 4-D action and
`corner2` RGB.

```bash
python scripts/collect_metaworld_rm_data.py \
  --tasks all \
  --output-root "$PWD" \
  --num-success 20 \
  --num-fail 20 \
  --max-episode-steps 200 \
  --image-size 128 \
  --failure-policy random \
  --reward-function-version v2 \
  --seed 42
```

Validate all datasets:

```bash
python scripts/validate_metaworld_rm_data.py \
  --tasks all \
  --minimum-episodes 20 \
  --output eval_results/metaworld_data_validation.json
```

Run automatic reward construction, train all eight visual RMs, evaluate held-out
episodes and export auto/dense/sparse replay files:

```bash
EPOCHS=100 \
NUM_WORKERS=16 \
NPROC_PER_NODE=1 \
PYTHON_BIN="$PWD/.venv/bin/python" \
./scripts/run_metaworld_rm_pipeline.sh 2>&1 | tee metaworld_rm_pipeline.log
```

## Reward semantics

The repository distinguishes:

- `auto label`: dense demonstration potential generated by stage discovery;
- `RM potential`: conservative minimum of the visual ensemble;
- `absolute RM reward`: `phi(s') + goal_bonus`;
- `PBRS reward`: `gamma * phi(s') * (1-done) - phi(s) + goal_bonus`;
- environment dense reward: privileged reference used only for diagnostics.

Evaluation success must always come from the environment, never from RM output.

## Reproducibility boundaries

- High label PRA is not proof of policy utility.
- RM quality must be evaluated on held-out episodes.
- Final acceptance requires online environment success, fixed interaction
  budgets and multiple random seeds.
- MetaWorld Reach-Wall currently has a negative strict terminal label gap and
  should be treated as a reward-construction risk.
- The smoke reports verify code paths, not the long-horizon curves from the
  paper figure.
